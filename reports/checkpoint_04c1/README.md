# Checkpoint 04C.1 — Focused global CatBoost anchor

This namespace is generated by:

```powershell
python tools\run_checkpoint_04c1.py
```

Checkpoint 04C.1 is intentionally narrow. It does **not** reopen the broad 03C.2
model-family search. It evaluates three CatBoost configurations inherited from
the frozen 03C.2 grid on the exact Checkpoint 04B pseudo-competition memberships.

Primary questions:

- does the C1 agronomic CatBoost anchor improve the target-matched pseudo-test RMSE?
- does a low CatBoost weight improve the stronger Local04D or Graph04D baseline?
- are CatBoost residuals sufficiently different to justify carrying it into 04F?
- does any gain survive a controlled leave-one-target-matched-split-out gate?

The default run uses GPU CatBoost and three deterministic seeds per candidate.
There is no automatic CPU fallback. CPU execution must be requested explicitly:

```powershell
python tools\run_checkpoint_04c1.py --catboost-task-type CPU --confirm-cpu y
```

Expected generated artifacts:

```text
pseudo_predictions.csv
split_metrics.csv
protocol_summary.csv
loso_anchor_gate_selection.csv
loso_anchor_gate_predictions.csv
residual_correlation.csv
actual_anchor_candidates.csv
checkpoint_04c1_report.json
checkpoint_04c1_report.md
```

The 59 actual-target predictions are candidate values only. Hidden FIRA target
values are never loaded or scored.
